Creating and Launching Trigger-based Forms (Campaigns)

Trigger-based forms are behavior-based forms that appear automatically when a visitor meets specific criteria. Unlike the standard "Always-on" Feedback Button, these forms are standalone and do not require a visible button to exist on the page.

1. Choosing Your Survey Type

To begin, click Create from the main dashboard and select Trigger-based Form. You must then choose between two primary formats:

  • Slide-out Survey: A subtle widget that slides in from the edge of the screen. Ideal for quick check-ins without interrupting the user journey.
  • Full-screen Survey: A high-impact modal that covers the page. Use this for critical research where you need the user's full attention.

2. Building the Survey (The Builder)

The builder is divided into Start Page, Form Page (for multi-page flows), and End Page.

Page Management & Logic

  • Multi-Page Flows: Click the + icon next to the page tabs to add additional form pages. You can rename or delete pages by clicking the three-dot menu on the tab.
  • Page Logic (Branching): Click Edit Settings on any page tab to configure conditional jumps. This allows you to skip pages or "jump" a user to the End Page based on their specific answers.
  • Discard Guard: If you try to exit the builder without saving, a "Discard Form" warning will appear to prevent accidental data loss.

Adding Content

Drag elements from the sidebar to the preview area:

  • Feedback elements: NPS, Rating, and Mood (emoji scales).
  • Input elements: Text Area, Input Text, and Email.
  • Choice elements: Dropdowns, Checkboxes, and Radio Buttons.
  • Formatting: Use Headers and Paragraphs to provide context or instructions.

3. Targeting: Defining the "Who" and "Where"

For detailed targeting options, see our Web Survey Targeting guide. Targeting rules work as "AND" conditions—a visitor must meet all enabled criteria for the survey to trigger.

4. Scheduling & Fatigue Management

Control the campaign lifecycle via the Schedule tab:

  • Activation: Choose to activate immediately, schedule a future start date, or save the campaign as "Off" to be toggled manually later.
  • Deactivation: Automatically stop the campaign on a specific date or after a certain number of responses (e.g., stop after 500 entries).
  • Reset Campaign: Define how often a user should see the survey again (e.g., every 30 days).
  • "Do Not Bother": Uses Local Storage to ensure a visitor only sees the survey once until the next reset. This persists even if the user closes the tab, but will be cleared if they wipe their browser cache.

5. Installation

  • The Snippet: Copy the unique JavaScript code and paste it into the global footer of your website.
  • CSP (Content Security Policy): If your site is highly secure, use the Include CSP Hash option in the Install tab to get the specific hashes required for your script-src and style-src headers. Learn more in our CSP Configuration guide.
  • Full-Page URL: If using the Full-screen format, you will also be provided with a direct Survey URL. This can be used as a standalone link in marketing emails or support signatures.

Pro-Tips for Success

  • Preview First: Use the Preview button in the builder to test your Page Logic and design before launching.
  • Avoid Overlap: Don't trigger multiple campaigns at the exact same moment on the same page; it can lead to a poor user experience and data conflicts.
  • Targeting Dependencies: If you only want to show Survey B to users who finished Survey A, use a custom cookie dropped on the "Success" event of Survey A.
Next steps: After launching, head to How to Analyse Your Results to track campaign performance.
