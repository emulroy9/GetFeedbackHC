Targeting Options for Trigger-based Forms

Targeting ensures that your survey is shown only to the most relevant users at the most opportune time. By setting specific page rules and behavioural triggers, you can increase response quality and avoid interrupting users who aren't in the right stage of their journey.

Section 1: Where (Page Targeting)

The Pages section defines the physical locations on your site where the survey is allowed to load.

  1. Navigate to Setup > Targeting and locate the Pages block.
  2. Add Page Rule: Select your matching logic:
    • Simple Match: Exact URL (e.g., https://example.com/pricing).
    • Contains: Any URL with a specific string (e.g., /checkout/).
    • Regex: For advanced pattern matching across multiple subdomains or dynamic paths.
  3. Multiple Rules: If you add more than one rule, use the logic toggle to decide if the user must be on a page that matches All rules or Any of the rules.

Section 2: Who (Audience Segmentation)

This section allows you to narrow your reach based on specific user data.

  • Custom Variables: This is where you apply the data you've configured in the Custom Variables Guide. You can set rules like: "Only show this survey if 'User_Tier' is 'Enterprise'."
  • Traffic Percentage: Use the slider to limit the survey to a random sample of your audience (e.g., 20% of visitors). This is ideal for high-traffic sites to prevent data overload and "survey fatigue."

Section 3: When (Behavioural Triggers)

Triggers decide the exact "moment of truth" for the survey to appear.

Standard Triggers

  • Immediately: The survey triggers as soon as the page loads.
  • Time on Page: Displays after a user has been on the page for a specific number of seconds.
  • Scroll Depth: Triggered when a user reaches a certain percentage (e.g., 50%) of the page length.
  • Exit Intent: Our script detects when a user's cursor moves toward the top of the browser to close the tab or change the URL.

Custom Events (JavaScript Triggers)

For actions that don't change the URL (like clicking a "Submit" button or seeing an error message), use a Custom Event.

  • Give your event a name in the UI (e.g., cart_error).
  • Ask your developer to trigger it via code: window.usabilla_live('trigger', 'cart_error');

Section 4: Device Targeting

Ensure a seamless experience by choosing which devices the survey is optimized for.

  • Toggle Desktop, Tablet, and Mobile on or off.
  • Note: If you are using a very complex form with many columns, it is often best to disable "Mobile" and create a separate, simplified Trigger-based form specifically for smaller screens.

Best Practices

  • The "One-Form" Rule: To maintain a high-quality user experience, GetFeedback will generally only show one active Trigger-based form per page view. If multiple Trigger-based forms target the same page, the one with the highest priority or most specific rule will win.
  • Test with Query Params: When testing, add a unique query parameter to your URL (e.g., ?test=true) and set a temporary targeting rule for that parameter so you can see the survey without affecting real customers.
